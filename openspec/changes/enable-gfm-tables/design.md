# Design: Enable GFM Table Parsing

## Technical Approach

Install `remark-gfm` v4 and register it in the lesson MDX pipeline after `remarkMath`, so GFM pipe tables parse into `<table>` elements. The existing `MarkdownTable` component is already mapped via `table: MarkdownTable` and activates automatically. Fix an unescaped `<` in lesson08 prose and tighten the H1 strip regex. Three files, zero new components.

## Architecture Decisions

### Decision: Plugin Ordering — `[remarkMath, remarkGfm]`

**Choice**: Remark pipeline: math first, GFM second.
**Alternatives considered**: GFM-first (risk: `$|x|$` in LaTeX confuses GFM table detection); both in either order (both operate during micromark parse phase, but ordering is explicit).
**Rationale**: `remark-math` tokenizes `$...$`/`$$...$$` into dedicated `inlineMath`/`math` MDAST nodes before `remark-gfm` scans text for pipe tables. This eliminates any theoretical conflict where a LaTeX pipe-table-lookalike triggers GFM. In practice GFM table detection runs at the micromark parse level regardless of order, so both work — but math-first is the defensive choice matching the spec (REQ-GFM-02).

### Decision: Dependency — `remark-gfm` ^4

**Choice**: `remark-gfm` v4 (latest stable major).
**Alternatives considered**: v3 (legacy CommonJS, would conflict with ESM toolchain).
**Rationale**: v4 is ESM-native, compatible with `unified` 11.x (used by `remark-math` ^6 and `next-mdx-remote` ^6). Install command: `source ~/.nvm/nvm.sh && nvm use 22 && npm install remark-gfm`. The `^4` range allows semver-compatible updates within v4.

### Decision: `<` Escape — Backslash in CommonMark Position

**Choice**: `\<10,000` (CommonMark backslash escape).
**Alternatives considered**: `&lt;` (interferes with MDX JSX parsing inside `<CalloutInfo>`); rewording (loses author framing per REQ-L08-02).
**Rationale**: Line 90 sits in a `<CalloutInfo>` block preceded by a blank line, making it a CommonMark paragraph where `\` escapes are honored. After MDX JSX parsing, `\<` becomes literal `<` in rendered output.

## Data Flow

```
remarkMath ($...$ → inlineMath/math nodes)
       │
       ▼
remarkGfm  (|...| text → table nodes, $ already protected)
       │
       ▼
rehypeKatex (math nodes → KaTeX HTML)
       │
       ▼
MDX compile → <table> elements in React tree
       │
       ▼
table: MarkdownTable (styled wrapper applied)
```

## Verification-First Step

Before wiring `remarkGfm` into `page.tsx`, run a standalone verification to confirm GFM tables parse inside `<Section>`-equivalent blocks:

```bash
node -e "
const {unified} = require('unified');
const remarkParse = require('remark-parse');
const remarkGfm = require('remark-gfm');
const md = '<div>\n\n| a | b |\n|---|---|\n| 1 | 2 |\n\n</div>';
const tree = unified().use(remarkParse).use(remarkGfm).parse(md);
const hasTable = tree.children.some(n => n.type === 'table');
console.log(hasTable ? 'PASS: table detected' : 'FAIL: no table');
process.exit(hasTable ? 0 : 1);
"
```

If it fails (low probability), fall back to the proposal-documented alternative: wrap table content in a `<MarkdownTable>` JSX component with `children` as a string. This is NOT the primary path.
